# Issue tracker: GitHub

Issues and specs live at https://github.com/ecochran76/auracall/issues. Use `gh` with explicit `--repo ecochran76/auracall`; use host-qualified API paths for API operations. The oracle-archive remote is not this tracker.

Read issues with `gh issue view NUMBER --repo ecochran76/auracall --comments`; list with `gh issue list --repo ecochran76/auracall --state open --limit 100 --json number,title,body,labels,author,comments` and paginate for exhaustive discovery.

Before mutations, follow `docs/dev/policies/0033-forge-issue-reporting.md`, `0034-github-issue-operations.md`, and `docs/dev/forge-issue-targets.json`. Verify the authenticated actor, target, capability, current issue state and existing labels. Use a body file for multiline issue/comment text and read back every mutation. Publishing to the tracker means creating a GitHub issue; fetching a ticket means reading its complete issue and comments.

Preserve issue, plan, branch/worktree and PR links under the repository traceability and integration policies. Checked-in plans supplement GitHub Issues; they do not replace this tracker.

## Pull requests as a triage surface

**PRs as a request surface: no.** External PRs are excluded from the issue triage queue. Normal PR review and integration remain governed by repo policy.

## Triage

Use `docs/agents/triage-labels.md`. Any issue or comment posted by the triage skill must begin with `> *This was generated by AI during triage.*`. Do not infer approval to transition issues from configuration setup.

Wayfinding labels, dependencies, assignees and other GitHub extensions require their own configured authority and capability checks; this setup does not authorize them.
